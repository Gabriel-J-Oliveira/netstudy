DNS + RESOLUÇÃO DE NOMES

Do nome ao endereço

O cliente conhece intranet.exemplo.local e precisa obter seu IPv4. Neste cenário, pergunta pelo registro A ao resolvedor 192.168.10.53, que responde 192.168.20.30.

Resolvedor: servidor consultado para obter a resposta DNS. Registro A: associação de um nome a um IPv4. Cache: resposta guardada temporariamente para reutilização enquanto válida.

DNS fornece a associação nome–endereço; não entrega a página, escolhe a rota ou comprova que o serviço web funciona.

Primeiro resolver, depois tentar acessar

CONSULTA · CLIENTE → RESOLVEDOR192.168.10.50 pergunta a 192.168.10.53 por intranet.exemplo.local.
RESPOSTA · RESOLVEDOR → CLIENTEDado do registro A: intranet.exemplo.local → 192.168.20.30.
DEPOIS · OUTRA COMUNICAÇÃOCom o IPv4, o cliente pode tentar acessar o servidor web. DNS não testa esse serviço.

O que cada evidência mostra?

nslookup mostra uma resposta DNS para o nome. ping 192.168.20.30 testa uma comunicação direta com o IP. Nenhum dos dois, isoladamente, comprova que a aplicação web em TCP 443 funciona.

Nome → resposta DNS → IPv4 conhecido → tentativa separada de acesso ao serviço

Ver terminal simulado do cliente

Comandos executados no cliente 192.168.10.50. As saídas são simuladas; nslookup consulta o resolvedor e não demonstra uso do cache local.

Use nslookup intranet.exemplo.local ou ipconfig /displaydns.
