DNS + RESOLUÇÃO DE NOMES · ÁREA 01

Nome não é destino de rede

O cliente conhece intranet.exemplo.local, mas precisa do IPv4 associado para alcançar o host. DNS fornece informação de endereçamento: não transporta a página, não escolhe a rota e não prova que o serviço está funcionando.

Nome → DNS → IPv4 do host

ÁREA 02 · CONSULTA

Request e Response

192.168.10.50 pergunta ao resolvedor 192.168.10.53 pelo nome. A resposta A neste cenário é 192.168.20.30.

ÁREA 03 · CACHE

Resposta reutilizada enquanto válida

Compare cache vazio e preenchido. Um cache válido pode evitar uma nova consulta, mas não demonstra que o serviço web está disponível agora.

ÁREA 04 · DIAGNÓSTICO

O que a evidência permite dizer?

Um nslookup resolvido não testa a rota, a conexão TCP 443 ou a aplicação web. Um ping direto ao IP também não prova que o nome foi resolvido.

Terminal simulado
Use nslookup intranet.exemplo.local ou ipconfig /displaydns.

Saídas simuladas apenas para este cenário.

ÁREA 05 · SÍNTESE

Da identificação ao serviço

Obtenha o IPv4 pelo nome antes de pensar no caminho e no endpoint da aplicação.

Nome → DNS → IPv4 → gateway/rota → TCP + porta → serviço
