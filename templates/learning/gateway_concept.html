DEFAULT GATEWAY + NEXT HOP · ÁREA 01

O que o host faz quando o destino está em outra rede?

Descobrir que é remoto cria uma nova pergunta

192.168.10.80LOCAL

Pertence a 192.168.10.0/24. ARP pode procurar o próprio destino.

192.168.20.50REMOTO

Não pertence a 192.168.10.0/24.

Para quem o primeiro frame deve ser entregue?

PC-A não consegue entregar diretamente, da forma estudada aqui, um frame Ethernet a PC-B, pois PC-B não faz parte de sua rede Ethernet local.

PC-A precisa entregar a comunicação a um dispositivo localmente alcançável que possa encaminhá-la em direção a outras redes.

Next hop, ou próximo salto, é o próximo dispositivo de Camada 3 para o qual uma comunicação deve ser encaminhada em seu caminho até o destino final.

PC-A não precisa alcançar PC-B diretamente naquele primeiro passo. Ele precisa alcançar quem poderá encaminhar a comunicação adiante.

ÁREA 02

A saída padrão para outras redes

PC-AIPv4 192.168.10.25Mask 255.255.255.0Default Gateway 192.168.10.1
O Default Gateway é o próximo salto utilizado pelo host quando o destino precisa ser alcançado através de outra rede e não existe uma rota mais específica aplicável.

Nesta aula trabalharemos com cenários simples em que o gateway padrão é a saída utilizada para destinos remotos.

O DESTINO IP DIZ ONDE A COMUNICAÇÃO QUER CHEGAR.O DESTINATION MAC DIZ PARA QUEM AQUELA ENTREGA ETHERNET LOCAL DEVE IR AGORA.

São diferentes e está correto. O endereço IP representa o destino da comunicação de Camada 3. O Destination MAC representa o destinatário daquela entrega Ethernet naquele enlace local.

Neste cenário sem tradução de endereços, o Destination IP continua representando PC-B enquanto o pacote é encaminhado.

SW1 lê Destination MAC RR e encaminha o frame a R1. Ele não decide usando 192.168.20.50. Ao chegar a R1, o frame cumpriu sua função naquele enlace; o pacote continua e o roteador precisará decidir como encaminhá-lo.

RAPID FIRE · 4 PERGUNTAS

1. Destino local: ARP procura quem?

Explique antes de revelar

Por que um pacote destinado a 192.168.20.50 pode sair de PC-A dentro de um frame cujo Destination MAC pertence ao gateway?

Resposta de referência

Porque PC-A identificou que 192.168.20.50 está fora de sua rede local. O destino IP continua sendo o host remoto, mas a primeira entrega Ethernet precisa chegar ao próximo salto local. Por isso o frame usa o MAC do gateway.
