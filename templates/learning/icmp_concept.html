ICMP + PING + TRACEROUTE · ÁREA 01

O que realmente descobrimos quando testamos a comunicação?

Ping observa uma troca ICMP

ICMP transporta mensagens de controle, erro e diagnóstico associadas à camada IP. O Ping envia um ICMP Echo Request e observa se recebe um Echo Reply.

OSI · CAMADA 3 — REDE
OBSERVAR PING

Inicie o percurso no laboratório.

PING TESTA UMA TROCA ICMP. ELE NÃO TESTA “TUDO”.

A troca completa tem duas mensagens, com origem e destino invertidos.

ÁREA 02 · MENSAGENS E PERDA

Uma pergunta, uma resposta

O Request segue de 192.168.10.20 para 192.168.50.30. O Reply volta com Source e Destination IP invertidos. Em uma rede real, o caminho de volta não precisa ser idêntico ao de ida.

Uma troca esperada não foi concluída durante esse teste; os números não identificam a causa.

PERDA É UMA MEDIÇÃO. NÃO É UMA CAUSA.

Também precisamos separar o que uma resposta — ou sua ausência — realmente permite concluir.

ÁREA 03 · EVIDÊNCIA NÃO É CAUSA

O resultado observado não revela sozinho a causa

Echo Reply demonstra conectividade IP suficiente para aquela troca ICMP naquele momento. Não comprova que DNS, uma porta TCP, uma aplicação ou um serviço web funcionem.

✓ REPLY

Uma resposta voltou do destino.

⏱ TIMEOUT

A resposta esperada não chegou no período previsto.

⚠ UNREACHABLE

Algum equipamento enviou uma mensagem ICMP explícita.

Request timed out.
Reply from 192.168.10.1: Destination host unreachable.

Timeout não é o mesmo que Destination host unreachable: no segundo caso houve uma mensagem explícita de algum ponto.

INTERPRETAR A EVIDÊNCIA

Observe o timeout no laboratório e revele a conclusão segura e os limites dessa conclusão.

Comece pela observação.

AUSÊNCIA DE RESPOSTA NÃO É UMA CAUSA. É APENAS UMA EVIDÊNCIA.

Ping observa uma troca. Traceroute controla a distância alcançada por cada sonda.

ÁREA 04 · TTL E TRACEROUTE

TTL controla até onde cada sonda pode ir

O TTL do IPv4 é reduzido a cada roteador. Ao chegar a zero, o roteador descarta a sonda e pode responder com ICMP Time Exceeded. Traceroute repete o teste com TTL crescente.

TTL LIMITA ATÉ ONDE O PACOTE PODE IR.
EXPLORAR TRACEROUTE

Escolha TTL de 1 a 4 e execute cada sonda para observar R1, R2, R3 e PC-B.

Escolha um TTL no laboratório.

C:\> tracert 192.168.50.30
  1    1 ms    1 ms    1 ms    192.168.10.1
  2    8 ms    7 ms    8 ms    10.0.0.2
  3   15 ms   14 ms   16 ms    10.0.1.2
  4   23 ms   22 ms   24 ms    192.168.50.30

Cada linha normalmente reúne várias sondas. Os tempos são respostas observadas, não uma medida de “velocidade”.

1 R1
2 *
3 R3
4 destino

Um hop silencioso não prova que parou de encaminhar: R3 e o destino responderam. Respostas ICMP podem ser filtradas ou limitadas.

As duas ferramentas fornecem evidências diferentes. Use o terminal para comparar os resultados.

ÁREA 05 · TERMINAL E SÍNTESE

Teste, observe, depois conclua

PING

Echo Request → Echo Reply voltou? Evidência de troca ICMP fim a fim.

TRACEROUTE

TTL 1, 2, 3… → pontos alcançados e respostas como ICMP Time Exceeded.

Explique antes de revelar

Por que Ping bem-sucedido não prova que uma aplicação funciona?

Ping testa uma troca ICMP. Echo Reply mostra que ela chegou e retornou; o serviço precisa ser testado separadamente.

Explique antes de revelar

Como Traceroute descobre os roteadores sem conhecer o caminho?

Envia sondas com TTL crescente. Ao chegar a zero, o roteador pode responder com ICMP Time Exceeded, revelando progressivamente os saltos.
