INTER-VLAN ROUTING · ÁREA 01

Como dispositivos em VLANs diferentes conseguem se comunicar?

VLAN 10 e VLAN 20 são contextos diferentes de Camada 2

VLAN 10PC-A · AA
CAMADA 2 TERMINA AQUI PARA ESSE CONTEXTO
VLAN 20PC-B · BB

O switch não trata VLAN 10 e VLAN 20 como um único domínio Ethernet. Simplesmente conhecer BB não faz um switch L2 atravessar diretamente de uma VLAN para outra.

ENTÃO PRECISAMOS DE QUÊ?

Inter-VLAN Routing é o uso de uma função de Camada 3 para encaminhar tráfego entre redes associadas a VLANs diferentes.
ROTEAR ENTRE VLANs NÃO REMOVE A SEPARAÇÃO ENTRE ELAS.
A COMUNICAÇÃO OCORRE ATRAVÉS DE CAMADA 3.

ÁREA 02

Para PC-A, a outra VLAN começa como um destino remoto

PC-A · VLAN 10192.168.10.20/24MAC AA · Gateway 192.168.10.1
PC-B · VLAN 20192.168.20.30/24MAC BB · Gateway 192.168.20.1

Resultado para A: REMOTO. Portanto, A usa o gateway alcançável em sua própria VLAN.

Esses números foram escolhidos para este cenário. O ID da VLAN não determina automaticamente qual sub-rede IPv4 deve ser usada.

PC-A fez sua parte. O frame chegou ao gateway. Agora a decisão passa para a função de Camada 3.

ÁREA 03

O frame termina. O pacote continua.

FRAME ETHERNETDestination R10TERMINA NESTE ENLACE
PACOTE IPv4Source 192.168.10.20Destination 192.168.20.30CONTINUA
FRAME = ENTREGA DE UM ENLACE.
PACOTE IP = COMUNICAÇÃO ENTRE REDES.

Destination IP 192.168.20.30 → Routing Table → 192.168.20.0/24 → diretamente conectada → saída VLAN 20.

VLAN 10 · Gateway 192.168.10.1FUNÇÃO L3VLAN 20 · Gateway 192.168.20.1

Uma única função/equipamento L3 pode possuir presença lógica nos dois contextos.

Por qual contexto o pacote deve continuar?

A rota foi escolhida. PC-B ainda precisa receber uma nova entrega Ethernet dentro da VLAN 20.

ÁREA 04

Uma nova rede significa uma nova entrega Ethernet

Na VLAN 20, a função L3 envia, se necessário, Who has 192.168.20.30?. PC-B responde: 192.168.20.30 is at BB.

ARP #1 · VLAN 10PC-A procura gateway192.168.10.1 → R10
ARP #2 · VLAN 20Gateway procura PC-B192.168.20.30 → BB
FRAME #1 · VLAN 10AA → R10IP 192.168.10.20 → 192.168.20.30
FRAME #2 · VLAN 20R20 → BBIP 192.168.10.20 → 192.168.20.30
O PACOTE CONTINUA. O FRAME MUDA.
MACs MUDARAM; IPs PERMANECERAM OS MESMOS NESTE CENÁRIO SEM NAT.

O roteador não “passou o mesmo frame”: recebeu um frame, processou o pacote IP, escolheu uma rota e criou a entrega do próximo enlace.

Como isso pode ser implementado?

Interfaces lógicas / função L3

Uma função L3 fornece gateways nos dois contextos.

Router-on-a-Stick

Um trunk SW1↔R1 transporta VLAN 10 e VLAN 20; subinterfaces fornecem 192.168.10.1 e 192.168.20.1.

G0/0.10 · VLAN 10
G0/0.20 · VLAN 20

O trunk preserva os contextos usando 802.1Q; ele não realiza routing. Router-on-a-Stick é uma forma de implementação, não a definição. Outra possibilidade é um switch com capacidade de Camada 3.

Da VLAN 10 até a VLAN 20

  1. B é remoto para A.
  2. A resolve 192.168.10.1→R10.
  3. Frame #1 AA→R10 carrega o pacote A→B.
  4. Frame termina na função L3; pacote permanece.
  5. Rota 192.168.20.0/24→VLAN20.
  6. ARP VLAN20 resolve B→BB.
  7. Frame #2 R20→BB carrega o mesmo pacote.
  8. SW1 entrega na Access VLAN20.
RESPOSTA B → A

B também classifica A como remoto, usa 192.168.20.1 e a função L3 escolhe 192.168.10.0/24.

1. Para A, B é local ou remoto?

Explique antes de revelar

Por que PC-A não envia simplesmente um frame diretamente para PC-B em outra VLAN?

Porque as VLANs são contextos separados de Camada 2 e PC-A identifica B como remoto. A entrega inicial vai ao gateway; a função L3 escolhe a rota e cria uma nova entrega Ethernet na VLAN de destino.
