INTER-VLAN ROUTING · ÁREA 01

Como dispositivos em VLANs diferentes conseguem se comunicar?

VLANs separam domínios de Camada 2

VLAN 10PC-A · MAC AA
DOMÍNIOS L2 SEPARADOS
VLAN 20PC-B · MAC BB

O switching L2 não encaminha diretamente um frame da VLAN 10 para a VLAN 20. A travessia exige uma função de Camada 3.

ROTEAR ENTRE VLANs NÃO REMOVE A SEPARAÇÃO ENTRE ELAS.
IDENTIFICAR A FUNÇÃO RESPONSÁVEL

No laboratório, acione o elemento que permite atravessar os dois domínios.

A função L3 permite a travessia. Antes disso, PC-A precisa decidir a quem entregar o primeiro frame.

ÁREA 02 · DECISÃO DO HOST

O destino é remoto para PC-A

PC-A · VLAN 10192.168.10.20/24MAC AA · Gateway 192.168.10.1
PC-B · VLAN 20192.168.20.30/24MAC BB · Gateway 192.168.20.1

As redes 192.168.10.0/24 e 192.168.20.0/24 são diferentes. PC-A não procura o MAC de PC-B na VLAN 10: ele precisa do MAC de seu gateway.

PREENCHER O ALVO ARP

Informe no laboratório qual IPv4 PC-A deve resolver primeiro.

O PRÓXIMO SALTO ETHERNET É O GATEWAY. O DESTINO IP CONTINUA SENDO PC-B.

Com R10 resolvido, PC-A consegue construir a primeira entrega Ethernet.

ÁREA 03 · O PRIMEIRO FRAME TERMINA

O frame termina. O pacote continua.

FRAME · VLAN 10AA → R10TERMINA NO ROTEADOR
PACOTE IPv4192.168.10.20 → 192.168.20.30CONTINUA

O roteador remove o frame recebido e consulta a tabela usando o Destination IP do pacote.

ACOMPANHAR E INSPECIONAR A ROTA

Avance até a consulta e selecione a linha que corresponde ao destino.

FRAME = ENTREGA DE UM ENLACE.
PACOTE IP = COMUNICAÇÃO ENTRE REDES.

A rota leva à VLAN 20. Agora o roteador precisa criar uma nova entrega Ethernet.

ÁREA 04 · NOVO ARP, NOVO FRAME

Os MACs mudam; os IPs permanecem

FRAME #1 · VLAN 10AA → R10IP 192.168.10.20 → 192.168.20.30
FRAME #2 · VLAN 20R20 → BBIP 192.168.10.20 → 192.168.20.30

Na VLAN 20, o roteador usa ARP para resolver 192.168.20.30 → BB e monta outro frame. O pacote IP não é reendereçado nesse processo.

ABRIR PACKET INSPECTOR E CONSTRUTOR

Inspecione os três momentos e construa os dois frames.

O PACOTE CONTINUA. O FRAME MUDA.
O PACOTE IP CONTINUA. O FRAME ETHERNET MUDA EM CADA SEGMENTO.
Router-on-a-Stick · implementação opcional

Um trunk pode transportar VLAN 10 e VLAN 20 até subinterfaces que oferecem 192.168.10.1 e 192.168.20.1. O trunk preserva os contextos com 802.1Q; ele não realiza routing.

Com as decisões isoladas, acompanhe agora o percurso completo no seu ritmo.

ÁREA 05 · PERCURSO COMPLETO

De PC-A até PC-B, passo a passo

Use o mesmo laboratório para iniciar, continuar e reiniciar as nove decisões. Não há reprodução automática.

INICIAR PERCURSO COMPLETO
  1. PC-A identifica o destino remoto.
  2. Escolhe e resolve o gateway R10.
  3. Cria o frame AA → R10.
  4. O roteador consulta a rota.
  5. Resolve BB e cria R20 → BB.
  6. PC-B recebe o mesmo pacote IP.

Avance uma decisão por vez no laboratório.

RETORNO · PC-B → PC-A

PC-B aplica a mesma lógica no sentido inverso: reconhece o destino remoto e cria primeiro um frame destinado a R20.

CLI · exploração opcional

R1# show ip route
C 192.168.10.0/24
C 192.168.20.0/24

Explique antes de revelar

Por que PC-A não envia simplesmente um frame diretamente para PC-B em outra VLAN?

Porque as VLANs são contextos separados de Camada 2 e PC-A identifica PC-B como remoto. A entrega inicial vai ao gateway; a função L3 escolhe a rota e cria uma nova entrega Ethernet na VLAN de destino.
