02 · STP CLÁSSICO

Como manter caminhos de reserva sem criar um círculo?

1 · PRIMEIRO, O PROBLEMA

Como manter o caminho de reserva?

Imagine três bairros ligados por estradas. Ter caminhos alternativos é ótimo quando uma estrada fica interditada. Na rede, porém, deixar todos os caminhos redundantes encaminhando frames pode criar um circuito sem fim.

O STP funciona como uma organização desse trânsito: mantém os caminhos necessários para a comunicação e deixa outros disponíveis para quando forem necessários.

Nenhum cabo precisa ser removido.

Onde a comparação com estradas termina

Frames não são veículos, e o STP não escolhe uma rota individual para cada destino. Ele organiza uma árvore lógica de encaminhamento para evitar ciclos ativos.

3 · UM PONTO DE REFERÊNCIA

Escolhendo a Root Bridge

Para organizar os caminhos, todos os switches precisam concordar sobre um ponto de referência. Esse switch recebe o nome de Switch eleito como referência para o cálculo da árvore lógica do STP.. Pense nele como o marco zero de um mapa; os outros switches comparam os caminhos até ele.

A Root Bridge não precisa ser o equipamento mais potente e nem todo tráfego precisa passar por ela.

Cada switch possui uma identidade usada pelo STP: o Bridge ID. Neste exemplo, vamos comparar primeiro a prioridade e, se houver empate, o endereço MAC.

Um detalhe do Bridge ID

Neste exemplo, mostramos prioridade e MAC para visualizar a comparação. Em equipamentos reais, o identificador de sistema estendido também participa do Bridge ID. A prioridade padrão comum é 32768 e as configurações de prioridade normalmente avançam em intervalos de 4096.

Apesar do nome “prioridade”, o menor valor tem preferência. Se os três valores empatam, o menor MAC desempata.

4 · COMPARAR CAMINHOS

O caminho mais curto nem sempre vence

Agora que temos um ponto de referência, cada switch precisa descobrir qual caminho utilizar para chegar até ele. O STP soma o custo de cada enlace do caminho.

Direto · SW1 → SW319
Via SW2 · SW1 → SW2 → SW34 + 4 = 8

Observe as duas somas e compare os caminhos antes de conferir.

O custo costuma estar relacionado à velocidade do enlace e também pode ser configurado. Ele não é uma leitura instantânea de congestionamento.

5 · ORGANIZAR AS PORTAS

Cada porta tem uma função e um estado

Root Port

Em cada switch que não é a raiz, é a porta que oferece o melhor caminho até ela.

Designated Port

É selecionada para oferecer a melhor informação de caminho até a raiz naquele segmento e encaminhar quando está em Forwarding.

Porta não designada

No cenário clássico desta aula, permanece em Blocking para impedir o ciclo de dados.

Papel e estado são coisas diferentes: Blocking descreve um estado, não um papel de porta.

BlockingRecebe informações STP, mas não encaminha dados de usuário.

ListeningParticipa das decisões antes de aprender endereços MAC.

LearningAprende endereços MAC, mas ainda não encaminha dados.

ForwardingEncaminha dados normalmente.

Disabled é diferente: a porta está fora de operação, por exemplo porque o enlace físico foi desconectado.

Configuração e previsões

Desafios orientados
  • Faça SW3 se tornar a Root Bridge sem alterar nenhum MAC.
  • Faça o caminho indireto ser preferido ao caminho direto.
  • Identifique uma porta em Blocking e observe o que acontece quando um enlace ativo falha.

Após mudar os valores, use “Recalcular STP” e percorra a demonstração novamente para comparar o resultado.
